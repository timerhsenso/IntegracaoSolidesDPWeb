1Como as peças se ligam

1.1 Componentes

PeçaO que éOnde roda
Serviço
IntegracaoSolidesDP		 Executável .NET (self-contained) que lê o banco do RHSenso e envia para a API do Sólides DP. Roda como serviço Windows, systemd ou container. É o único componente que fala com o Sólides DP e o único que conhece o token. Servidor com acesso ao SQL Server e saída HTTPS para employer.tangerino.com.br:443.
Web
IntegracaoSolidesDP.Web		 Aplicação ASP.NET Core (IIS) para acompanhar e operar: lê o histórico gravado pelo serviço, versiona a configuração e grava pedidos numa fila. Login próprio com perfis Consulta, Operador e Admin. IIS com o Hosting Bundle do .NET. Só precisa de acesso ao SQL Server.
Banco
bd_rhu_adn		 O mesmo banco do RHSenso. O serviço lê o dbo e escreve só no schema solidesdp. A Web escreve em solidesdp (configuração, fila, auditoria) e em solidesdp_auth (usuários). SQL Server 2019 ou superior.

1.2 Quem fala com quem

NavegadorUsuário da Web (HTTPS)
→
Webgrava pedido em solidesdp.comando e versões em solidesdp.configuracao
→
SQL Serverfila, configuração, histórico
←
Serviçolê a fila a cada Gestao:IntervaloComandos, executa e grava o resultado

Sólides DPAPI REST (token)
  • A Web nunca chama a API do Sólides DP. Se o serviço estiver parado, os pedidos ficam esperando, e a Web avisa no Painel depois de 2 minutos.
  • O serviço atende um pedido por vez e só entre execuções. Durante uma sincronização longa, os pedidos aguardam.
  • Duas execuções da mesma instância nunca rodam juntas (lock sp_getapplock). Uma execução pedida enquanto outra roda é descartada, com o aviso "Outra execução em andamento".
  • Para a Web funcionar, o serviço precisa estar com Gestao:Habilitada = true. Sem isso, a Web mostra apenas o aviso de que o banco não foi preparado.

Tabelas e colunas do schema solidesdp são documentadas no próprio banco (extended property MS_Description, visível no SSMS). As tabelas solidesdp.* são criadas pelo próprio serviço na primeira execução (ou no --check-config). As de solidesdp_auth são criadas pela Web ao iniciar (migrations). Configuração, fila, execuções e auditoria só recebem INSERT: nada é apagado pela aplicação.

2Configuração do serviço

2.1 Onde fica e precedência

O arquivo appsettings.json fica na pasta de instalação, junto do executável (no Windows, por padrão, C:\Services\IntegracaoSolidesDP; no Linux, /opt/integracao-solidesdp). Atualizações do pacote nunca sobrescrevem esse arquivo.

Cada chave pode vir de três lugares. O de baixo vence o de cima:

  1. appsettings.json
  2. variável de ambiente, com __ no lugar de : (ex.: SolidesDP__Token)
  3. argumento de linha de comando (ex.: --Execution:Interval=00:15:00)

O serviço lê a configuração do servidor só ao iniciar. Depois de alterar o appsettings.json ou uma variável de ambiente, reinicie o serviço. As regras de negócio alteradas na Web não precisam de reinício (veja 2.3).

2.3 Regras de negócio com a gestão ligada

As demais chaves da seção Sync (modo simulação, go-live, filtros, escala, férias, travas...) são as regras de negócio. Com Gestao:Habilitada = true:

  • Na primeira execução, o serviço copia a seção Sync do appsettings.json para o banco como versão 1.
  • Daí em diante, vale o que está no banco, alterado pelo Admin na tela Configuração da Web. Mudar essas chaves no appsettings.json (ou na linha de comando) não tem efeito.
  • Continuam vindo do servidor: ConnectionStrings, SolidesDP, Gestao, Execution, Sync:InstanceName e Sync:ReportDirectory.
  • Cada execução usa a versão vigente no momento em que começa e registra o número dela em solidesdp.runs.config_versao.
  • Uma versão inválida não chega à API: a execução é registrada como falha com config_invalid e o motivo.
  • Cada empresa é uma conta do Sólides DP, com o seu token. Cada execução roda as empresas habilitadas uma depois da outra, e cada empresa vira uma linha em solidesdp.runs. Uma empresa com problema (sem token, go-live faltando) falha sozinha; as outras seguem.
  • Empresa inativa no RHSenso (temp1.flativo) e filial inativa (test1.flativofilial) ficam fora do escopo: nada é enviado e ninguém é desligado por isso.
  • Enquanto nenhuma empresa foi configurada na Web, vale uma empresa só: a de Sync:EmpresasIncluidas, com o SolidesDP:Token.
  • Com a integração desativada na Web, o serviço não faz execuções reais (agendadas, pedidas ou de linha de comando). A simulação continua permitida.

A explicação de cada regra está na Web, em Ajuda › Configuração. Com a gestão desligada, as mesmas chaves valem direto do appsettings.json (veja o README.md).

2.4 Segredos

  • Prefira variáveis de ambiente para a senha do banco e o token: ConnectionStrings__Rhu e SolidesDP__Token.
  • Windows: variáveis de ambiente do sistema (o serviço roda como LocalSystem) ou, com autenticação integrada, Integrated Security=True na connection string e a conta do serviço trocada em services.msc.
  • Linux: arquivo /etc/integracao-solidesdp.env com permissão 600. Docker: -e ou secrets do orquestrador.
  • O token de cada empresa é cadastrado na Web e gravado cifrado no banco; nunca aparece de volta na tela. Guarde a Gestao:ChaveTokens/Web:ChaveTokens como segredo (variável de ambiente Gestao__ChaveTokens e Web__ChaveTokens), nunca no repositório.
  • Nunca mande token por chat, e-mail ou commit. Se isso acontecer, gere um token novo no Sólides DP (Empregador › Integrações) e revogue o antigo.

3Agendamento das execuções

O próprio serviço agenda as execuções. Não use o Agendador de Tarefas do Windows nem o cron. Informe exatamente uma das opções:

ModoExemploComportamento
Intervalo"Interval": "00:30:00"Uma execução a cada 30 minutos, contados do fim da anterior. Com RunOnStartup, a primeira roda logo que o serviço inicia.
Horários fixos"TimesOfDay": ["07:00", "13:00", "18:30"]Executa nesses horários, no fuso de Execution:TimeZone. Apague a linha Interval do arquivo.
 
// appsettings.json — horários fixos (sem a linha "Interval")
"Execution": {
  "TimesOfDay": [ "07:00", "13:00", "18:30" ],
  "TimeZone": "America/Bahia"
}
  • Depois de mudar o agendamento, reinicie o serviço. O log mostra a próxima execução calculada: "Próxima execução em AAAA-MM-DD HH:MM:SS UTC" (atenção: em UTC, 3 horas à frente de Brasília/Bahia).
  • Fora do agendamento, o usuário com perfil Operador pode pedir uma execução na Web (Pedidos ao serviço › Executar agora).
  • Na carga inicial, prefira intervalo curto (15 a 30 min) para acompanhar o progresso. No dia a dia, 30 a 60 minutos atendem bem.
  • Uma execução sem mudanças no RHSenso não faz nenhuma chamada de escrita ao Sólides DP. O custo de uma frequência maior é basicamente a leitura do banco.

Primeiro acesso

Numa instalação nova, sem usuários, abra https://localhost/<site>/PrimeiroAcesso num navegador no próprio servidor e crie o primeiro administrador. A tela recusa acessos remotos e deixa de existir assim que há um usuário. Os demais usuários são criados pelo Admin em Usuários.

Segurança

  • Somente HTTPS (HSTS fora de Development). Cookie de login HttpOnly, Secure e SameSite=Strict, válido por 8 horas com renovação por uso.
  • As chaves que protegem o cookie ficam no banco: a reciclagem do app pool não derruba ninguém.
  • Senha com no mínimo 8 caracteres, maiúscula, minúscula e número. Bloqueio de 15 minutos após 5 erros.
  • Desativar um usuário ou trocar o perfil vale em até 1 minuto, mesmo com a sessão aberta.

5Comandos em prompt (linha de comando)

O mesmo executável do serviço aceita comandos avulsos. Eles usam o appsettings.json da pasta de instalação, gravam no mesmo banco e aparecem na Web (origem "Linha de comando").

5.1 Como chamar

InstalaçãoComo rodar
WindowsPowerShell como Administrador, na pasta de instalação: cd C:\Services\IntegracaoSolidesDP e depois .\IntegracaoSolidesDP.exe <comando>
Linuxsudo -u integracao-solidesdp /opt/integracao-solidesdp/IntegracaoSolidesDP <comando>
Dockerdocker run --rm -e ... ghcr.io/rhsenso/integracaosolidesdp:<versão> <comando> (as mesmas variáveis do container do serviço)

Pode rodar com o serviço ligado. Se uma execução do serviço estiver em andamento na mesma empresa, um --run-once ou --dry-run é descartado pelo lock ("Outra execução em andamento"). Tente de novo em seguida.

--empresa N restringe qualquer comando à empresa N (cada empresa é uma conta do Sólides DP). Sem ele, --run-once, --dry-run e --check-config passam por todas as empresas habilitadas; --discover e --reconcile exigem a empresa quando há mais de uma.

5.2 Lista de comandos

5.3 Códigos de saída

Úteis em scripts e no monitoramento ($LASTEXITCODE no PowerShell, $? no Linux):

CódigoSignificado
0Sucesso. Em --run-once/--dry-run: execução Concluída sem erros.
1Falha. --check-config/--discover: algum [ERRO]. --run-once/--dry-run: execução concluída com erros, falhou ou não foi realizada (lock ou integração desativada). A última linha mostra o status e o caminho do relatório.
2Configuração do servidor inválida (a lista de problemas sai no console), ou --reconcile encontrou ausentes ou não verificáveis.

5.4 Passar configuração na linha de comando

Qualquer chave pode ir como argumento --Secao:Chave=valor, só para aquele comando, sem mexer no arquivo:

.\IntegracaoSolidesDP.exe --check-config --ConnectionStrings:Rhu="Server=sql02;Database=bd_rhu_adn;Integrated Security=True;TrustServerCertificate=True"

Com a gestão ligada, as regras da seção Sync vêm do banco, e argumentos como --Sync:DryRun=false são ignorados. Para mudar regra, use a tela Configuração da Web. A exceção é o próprio --dry-run, que sempre força a simulação.

5.5 Exemplos

# Conferir tudo depois de trocar o token ou a senha do banco
.\IntegracaoSolidesDP.exe --check-config

# Ids de escala e regra de ponto da conta da empresa 15
.\IntegracaoSolidesDP.exe --discover --empresa 15

# Simular só a empresa 15 e abrir o relatório no Excel
.\IntegracaoSolidesDP.exe --dry-run --empresa 15
Invoke-Item (Get-ChildItem .\reports\run-*.csv | Sort-Object LastWriteTime | Select-Object -Last 1).FullName

# Conferência semanal e, se confirmado com o RH, nova busca dos ausentes pelo CPF
.\IntegracaoSolidesDP.exe --reconcile --empresa 15
.\IntegracaoSolidesDP.exe --reconcile --repair --empresa 15
.\IntegracaoSolidesDP.exe --run-once --empresa 15

6.3 Relatórios de execução

  • Cada execução grava reports/run-*.csv (abre no Excel) e reports/run-*.json, com os itens com falha, bloqueados e ignorados e o motivo de cada um.
  • A pasta não é limpa automaticamente. Com execução a cada 30 minutos, são cerca de 100 arquivos por dia. Recomenda-se uma tarefa de limpeza mensal, mantendo 90 dias, por exemplo:
Get-ChildItem C:\Services\IntegracaoSolidesDP\reports -File |
  Where-Object LastWriteTime -lt (Get-Date).AddDays(-90) | Remove-Item

O histórico completo continua no banco (solidesdp.runs e solidesdp.run_items) e na Web.

6.4 Consultas úteis no banco

-- Últimas execuções
SELECT TOP 20 started_at, finished_at, cdempresa, status, dry_run, triggered_by,
       solicitado_por, config_versao, error_message
FROM solidesdp.runs ORDER BY started_at DESC;

-- Colaboradores vinculados da empresa 15: criados x vinculados pelo CPF
SELECT origem, status, COUNT(*) AS qtd
FROM solidesdp.colaborador_vinculo WHERE cdempresa = 15
GROUP BY origem, status;

-- Pedidos da Web que ainda esperam o serviço
SELECT id, tipo, solicitado_por, solicitado_em
FROM solidesdp.comando WHERE status = 'pendente';

-- Configuração em vigor (instância default)
SELECT TOP 1 * FROM solidesdp.configuracao
WHERE instance_name = 'default' ORDER BY versao DESC;

Consultas só de leitura. Não altere as tabelas solidesdp.* à mão: o estado guarda o vínculo com os registros do Sólides DP, e uma edição errada pode gerar cadastro duplicado lá.

7Solução de problemas no servidor

Os problemas de cadastro (CPF, cargo, CNPJ...) estão na Web, em Ajuda › Deu problema, e agora?. Aqui ficam os que dependem do TI.

SintomaCausa provável e solução
Serviço não inicia, ou para logo após iniciar Rode .\IntegracaoSolidesDP.exe --check-config no console: a configuração inválida aparece listada (código de saída 2). Confira também o log do dia e o Visualizador de Eventos do Windows.
"Informe exatamente um entre Execution:Interval e Execution:TimesOfDay" As duas chaves estão preenchidas, ou nenhuma. Deixe só uma e apague a linha da outra.
Web mostra "O serviço ainda não preparou o banco" Gestao:Habilitada está false, ou o serviço ainda não rodou depois de ligada. Ligue, reinicie o serviço (ou rode --check-config) e recarregue a Web.
Pedidos da Web parados em "Aguardando o serviço" Serviço parado, gestão desligada, Web:InstanceName diferente de Sync:InstanceName, ou uma execução longa em andamento. Verifique nessa ordem.
Sólides DP recusou o token (HTTP 401/403) Token inválido, revogado ou da conta errada. Gere outro no Sólides DP (Empregador › Integrações), atualize SolidesDP__Token e reinicie.
Falha de conexão/timeout com o Sólides DP Saída HTTPS bloqueada, proxy ou certificado. Teste no servidor: Test-NetConnection employer.tangerino.com.br -Port 443.
source_empty: nenhum colaborador lido Connection string apontando para outro banco, ou filtros da Configuração (piloto, empresas) que não casam com nada. A trava impede que um banco vazio leve a desligamentos em massa.
"tabelas ausentes em dbo" no --check-config O login não tem leitura no dbo ou o banco não é o do RHSenso. Revise o db_datareader do login.
Erro de permissão ao criar tabelas solidesdp O login do serviço precisa ser dono do schema solidesdp e ter CREATE TABLE (script em INSTALL.md, seção 1).
Serviço recusa iniciar: "O estado foi gravado com a chave de colaborador ..." A versão instalada usa outra forma de identificar o colaborador. Não force. Volte a versão anterior e fale com a RHSenso antes de atualizar.
Execução "Em andamento" que nunca termina O serviço foi parado no meio. Na próxima execução ela é marcada como Falhou automaticamente. Se o serviço estiver rodando e travado, reinicie-o.
Web não abre (erro 500.30 no IIS) Hosting Bundle do .NET ausente, connection string vazia ou sem acesso ao banco. Veja o log da Web e o Visualizador de Eventos (origem "IIS AspNetCore Module").
Tela Primeiro acesso diz "somente no servidor" Por segurança, o primeiro administrador só é criado num navegador aberto no próprio servidor (localhost).
Todos os usuários Admin perderam o acesso Um Admin pode redefinir a senha de outro. Sem nenhum Admin ativo, fale com a RHSenso: a recuperação é feita no banco (solidesdp_auth) com procedimento assistido.
